# Симулятор БПЛА — задания 1 и 2

Учебное приложение на **C++17 и Qt Widgets** для практических работ № 1–2 по дисциплине «Программное обеспечение объектов наземной инфраструктуры». Выполнены два задания из методических рекомендаций: движение по периметру квадрата и полет к заданной точке.

## Что реализовано

| Задание | Реализация |
| --- | --- |
| **1. Базовая сцена и движение по периметру** | Сцена размером 800 × 600, красный круг диаметром 20, стартовая позиция (50, 50). Кнопка запускает движение по квадрату: (50, 50) → (250, 50) → (250, 250) → (50, 250) → (50, 50). |
| **2. Полет к заданной точке** | Поля X и Y задают цель. БПЛА летит по прямой из текущей позиции, останавливается у цели и показывает сообщение «Цель достигнута». |

В обоих режимах таймер срабатывает каждые **20 мс**, а шаг движения составляет **2 пикселя**. При обычной работе это около 100 пикселей в секунду; фактическая частота зависит от обработки событий системой.

Координаты обозначают левый верхний угол ограничивающего квадрата круга. Начало координат находится слева вверху сцены, X увеличивается вправо, Y — вниз. Допустимы целые **X от 0 до 780** и **Y от 0 до 580**: круг диаметром 20 полностью остается в пределах сцены.

## Запуск в Qt Creator

Требуются Qt **5.15 или 6.x**, модуль Widgets и компилятор с поддержкой C++17. Для сборки через CMake также нужен CMake 3.16 или новее.

### Windows 10/11, MinGW

1. Установите Qt через [официальную страницу загрузки](https://www.qt.io/download-qt-installer-oss). Выберите Qt Creator, одну версию Qt 5.15/6.x для MinGW и соответствующий MinGW.
2. Скачайте репозиторий и распакуйте его, например, в `C:\Projects\uav_simulator`. Путь без кириллицы помогает избежать проблем с инструментами сборки.
3. В Qt Creator выберите **File → Open File or Project** и откройте `uav_simulator.pro` либо `CMakeLists.txt`.
4. Выберите **Desktop Qt ... MinGW** Kit для установленной версии Qt. Компилятор и библиотеки Qt должны соответствовать друг другу.
5. Нажмите **Configure Project**, затем **Run** (`Ctrl+R`).

### Ubuntu/Linux, GCC

Установите зависимости для Qt 6:

```bash
sudo apt update
sudo apt install build-essential cmake qt6-base-dev qtcreator
```

Для Qt 5 используйте вместо `qt6-base-dev` пакет `qtbase5-dev`:

```bash
sudo apt install build-essential cmake qtbase5-dev qtcreator
```

Откройте `CMakeLists.txt` или `uav_simulator.pro` в Qt Creator, выберите Desktop Kit с GCC и нужной версией Qt, настройте проект и нажмите **Run**. Если Kit не найден, проверьте **Preferences/Options → Kits**: версия Qt и C++-компилятор должны быть назначены.

## Сборка через CMake в Ubuntu

В терминале перейдите в папку с `CMakeLists.txt` и выполните:

```bash
cmake -S . -B build -DBUILD_TESTING=ON
cmake --build build --parallel
./build/uav_simulator
```

CMake обнаруживает установленную Qt 5 или Qt 6. Если Qt установлена через Online Installer и не находится автоматически, укажите каталог комплекта Qt при настройке, например:

```bash
cmake -S . -B build -DCMAKE_PREFIX_PATH=/opt/Qt/6.8.3/gcc_64 -DBUILD_TESTING=ON
```

Замените путь на реальный каталог вашей установки. При смене версии Qt используйте новую папку сборки, например `build-qt5` или `build-qt6`.

## Как пользоваться

1. После запуска круг находится в точке **(50, 50)**.
2. Нажмите **«Старт: полёт по квадрату»** (`btnStart`). Круг будет проходить четыре стороны непрерывно.
3. Введите координаты цели в поля `lineEditX` и `lineEditY`, например **X = 600, Y = 400**.
4. Нажмите **«Лететь к точке»** (`btnFly`). Режим квадрата сменится прямым полетом из текущей позиции.
5. После прибытия таймер остановится, а `labelStatus` покажет **«Цель достигнута»**. Можно указать следующую цель и снова нажать кнопку полета.

Пустые поля, нецелые значения и координаты вне допустимого диапазона не запускают новый полет; уже начатое движение продолжается. При выборе уже достигнутой цели программа сразу сообщает о прибытии.

## Логика движения

Для полета к точке вычисляется вектор от текущей позиции к цели:

```text
dx = targetX - x
dy = targetY - y
dist = sqrt(dx * dx + dy * dy)
```

При `dist > 2` направление нормализуется, затем умножается на шаг 2 пикселя:

```text
x += 2 * dx / dist
y += 2 * dy / dist
```

При `dist <= 2` оставшееся расстояние не превышает один шаг: координаты устанавливаются точно в цель. В режиме полета к точке таймер останавливается и состояние меняется на `Idle`; в квадратном режиме выбирается следующая вершина. В методических рекомендациях приведен допуск 3 пикселя; здесь он уменьшен до длины шага, чтобы каждый шаг был не больше 2 пикселей и не происходило перелета через цель. Нулевое расстояние обрабатывается до деления, поэтому деления на ноль нет.

В квадратном режиме направление меняется при достижении каждой вершины. Кнопка запуска квадрата возвращает БПЛА в (50, 50) и начинает обход сначала.

## Проверка

Автоматические проверки используют Qt Test. После сборки с `-DBUILD_TESTING=ON` запустите:

```bash
QT_QPA_PLATFORM=offscreen ctest --test-dir build --output-on-failure
```

Переменная `QT_QPA_PLATFORM=offscreen` позволяет выполнить проверки виджетов без открытого окна. Для обычного интерактивного запуска эту переменную задавать не нужно. GitHub Actions запускает сборку и проверки при изменениях в репозитории; результат конкретного запуска виден на вкладке **Actions**.

Для ручной проверки:

- Нажмите запуск квадрата: круг должен поворачивать в четырех вершинах и повторять маршрут.
- Задайте цель (600, 400): круг должен двигаться по прямой и остановиться точно в указанной точке.
- Задайте текущую точку: сообщение о достижении должно появиться сразу.
- Проверьте границы (0, 0) и (780, 580): круг должен оставаться внутри сцены.
- Попробуйте пустое поле, отрицательное число и X = 781: новый полет не должен запускаться.
- Во время полета укажите другую цель: движение должно продолжиться к новой цели.
- Снова нажмите запуск квадрата: маршрут должен начаться из (50, 50).

## Ответы на контрольные вопросы

**1. Чем различаются QGraphicsScene и QGraphicsView?** Сцена хранит графические объекты, их положение и состояние. Вид отображает сцену в окне и передает ей события пользователя. В проекте `scene` содержит круг, а `graphicsView` показывает его. Одну сцену можно отображать в нескольких видах. [Документация Qt](https://doc.qt.io/qt-6/graphicsview.html).

**2. Как работают сигналы и слоты?** Объект сообщает о событии сигналом, а подключенный слот выполняет обработку. В проекте сигнал `QTimer::timeout` подключен к `MainWindow::moveUAV`: каждое срабатывание таймера вызывает следующий шаг движения. [Документация Qt](https://doc.qt.io/qt-6/signalsandslots.html).

**3. Зачем нормализовать вектор?** Деление `(dx, dy)` на его длину дает направление длиной 1. Умножение на скорость задает одинаковый шаг 2 пикселя независимо от расстояния до цели и направления, в том числе по диагонали.

**4. Как проверить пересечение объектов?** Для простой проверки прямоугольников можно вызвать `itemA->sceneBoundingRect().intersects(itemB->sceneBoundingRect())`: оба прямоугольника уже находятся в координатах сцены. Для проверки самих фигур используется `itemA->collidesWithItem(itemB)`. Обнаружение столкновений относится к заданию 7 и в выбранные два задания не входит. [Документация Qt](https://doc.qt.io/qt-6/graphicsview.html).

**5. Зачем нужен допуск, например 3 пикселя?** Шаг движения и дробные координаты могут не дать точного совпадения с целью на очередном кадре. Проверка расстояния предотвращает перелет через цель и бесконечное движение около нее. В этой реализации допуск равен шагу, то есть 2 пикселям: последний шаг сокращается до оставшегося расстояния, конечные координаты становятся точными и таймер останавливается.
